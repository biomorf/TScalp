# TScalp: расширенный доступ (Termux + SSH)

Этот файл — SSoT по режиму доступа и механике канала. Правила кода, git и документации — в `AGENTS.md`, здесь не дублируются.

## 1. Первое действие сессии

Прочитай `AGENTS.md` в корне текущей директории и строго соблюдай его правила. Он важнее этого файла. Индекс — `AGENTS/AGENTS.md`, уроки — `AGENTS-LESSONS.md`.

## 2. Режим работы: строго только чтение

Ассистент **никогда не изменяет состояние репозитория**. Без исключений, без обходных путей, без «по умолчанию».

**Разрешено:** читать файлы и показывать их содержимое.

**Запрещено всегда:**

- создавать, править, перемещать и удалять файлы — любым способом (`>` и `>>`, `sed -i`, `tee`, `mv`, `rm`, `touch`, редакторы, `docs_add` / `docs_cut` с `--apply`, `docs_normalize --apply`, `docs_rebuild_index --apply`), включая правку самого этого файла;
- любые операции, меняющие git: `git add`, `git commit`, `git push`, `git checkout`, `git switch`, `git stash`, `git merge`, `git revert`, `git tag`;
- деструктивные команды: `git reset --hard`, `git clean -f`, `git push --force`, `git branch -D`, `git push --delete`, `git remote remove`, `rm -rf`, `find -delete`, `chmod -R`, `truncate`;
- сборка и тесты, создающие артефакты: `./gradlew …`, `adb install`.

**Изменения выполняются только так:** ассистент выдаёт готовый блок в чате, пользователь применяет его локально. Блок — по `4i` шаблон 1; правки `.md` — по `4c`.

## 3. Диагностика по репозиторию

Любая команда, обращённая к репозиторию (`git status`, `git log`, `git diff`, `docs_lint.py`, `grep`, `ls`, `cat`), выполняется **только после явного утвердительного ответа пользователя** на конкретный запрос.

- Согласием считается только явное «да» / «запускай» / «проверь».
- Молчание, отсутствие возражения, ответ на другой вопрос, «раньше разрешал» — **не согласие**.
- Разрешение даётся на один запрос и на перечисленные в нём команды.

## 4. Механика канала (проверено на практике)

- Подключение: `ssh` из песочницы в Termux — алиас `termux` (127.0.0.1:8022, ключ, положенный Cuplivo).
- **Работает только подача команд на stdin login-shell'а:**

```bash
printf 'cd ~/brojects/TScalp\ngit status --short\nexit\n' | ssh termux
```

- **`ssh termux 'команда'` не выполняется:** Termux-инициализация обрабатывает rc-файлы и теряет аргумент `-c`; команда не запускается, код возврата 0. Не пытаться «починить» это правкой rc-файлов пользователя.
- **`scp` и `sftp` непригодны:** rc-файлы пишут отладочный вывод в протокол → `Received message too long`.
- **Передача файла в проект** — heredoc в stdin-shell:

```bash
{ printf 'cd <корень>\ncat > <путь> << "EOF"\n'; cat <локальный файл>; printf 'EOF\nexit\n'; } | ssh termux
```

  Альтернатива, предпочтительная для пользователя: блок в чате, который он применяет сам.
- **Вывод содержит шум** (`DEBUG:`, `hi`) из rc-файлов — фильтровать: `| tr -d '\r' | grep -vE '^DEBUG|^\s*$|^hi$'`.
- **Коммиты из ssh невозможны:** `commit.gpgsign=true`, pinentry в неинтерактивной сессии не находит tty → `fatal: failed to write commit object`. Коммиты делает пользователь локально. Файлы, попавшие в индекс, остаются в индексе — это нормальное состояние, а не ошибка.

## 5. Если правило мешает

Ассистент не толкует это правило и не ищет обходных путей. Нужна запись или диагностика — **просит разрешение** и ждёт. Менять рамку может только пользователь, явно.

## 6. Границы рабочей области

- Работать только внутри корня проекта: `git rev-parse --show-toplevel`.
- Никаких `../`, никакого сканирования `$HOME`, никаких обращений за пределы проекта.
- Пути — относительные от корня: `./app/src/...`, `./gradlew`.

## 7. Среда

Termux: нет `/usr/bin`, используй `$PREFIX/bin`, `$PREFIX/etc`, `$PREFIX/tmp`; `sudo` и `systemctl` недоступны. Сборку запускает пользователь, с системным AAPT2:

```bash
./gradlew assembleDebug -Pandroid.aapt2FromMavenOverride="$PREFIX/bin/aapt2"
```

Ограничения по памяти и порядок работы — `AGENTS.md` → `code-workflows`.
